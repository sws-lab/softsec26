# Witness validation exercise

This exercise shows a small witness-based workflow:

1. compile and run the original C program,
2. use Goblint to generate and validate a YAML witness,
3. inject the witness into the program and run the instrumented version.

Run the commands below from the `witness-validation` directory.

## Quick start with Docker or Podman

Build the prepared toolchain image:

```bash
podman build -t witness-validation .
```

You can use `docker` instead of `podman` if that is what you have installed.

Start an interactive shell in the image:

```bash
podman run -it --rm witness-validation
```

Inside the container, run the full exercise:

```bash
make
```

This runs the default `all` target, which performs the plain run, witness
validation, witness injection, and injected run.

## Apple Silicon Macs

The Goblint base image used by this exercise is published for Linux `amd64`, but
not for Linux `arm64`. On an Apple Silicon Mac, force the build and run platform
to `linux/amd64`:

```bash
podman build --platform linux/amd64 -t witness-validation .
podman run --platform linux/amd64 -it --rm witness-validation
```

With Docker, use the same platform setting:

```bash
docker build --platform linux/amd64 -t witness-validation .
docker run --platform linux/amd64 -it --rm witness-validation
```

This runs through x86_64 emulation, so the image build can be noticeably slower.
If Podman still cannot run the image, Docker Desktop is usually the simplest
fallback on macOS.

## Useful targets

Run the original program only:

```bash
make vanilla
```

Generate and validate the witness:

```bash
make validate
```

Inject the witness and run the instrumented program:

```bash
make inject
```

Remove generated files:

```bash
make clean
```

Generated files are written to `out/`, including:

- `out/witness.yml`: the witness generated by Goblint,
- `out/example.injected.c`: the source file after witness injection,
- `out/vanilla`: the compiled original program,
- `out/example.injected`: the compiled injected program.

## Editing the witness

After `make validate` has generated `out/witness.yml`, you can edit that file
manually and rerun the validator:

```bash
make validate
```

For example, try changing one of the invariants or assumptions in the witness.
The goal is to see whether the validator accepts the modified witness or reports
that it no longer matches the program.

You can also run the injection step after editing the witness:

```bash
make inject
```

This rebuilds the injected program from the edited witness and then executes it
with the current `ARGS` value.

## Changing the program arguments

The example program expects:

```bash
./program LENGTH [OFFSET]
```

The Makefile passes these through the `ARGS` variable. The default is:

```bash
ARGS="1000 4"
```

To use different arguments, override `ARGS` when invoking `make`:

```bash
make vanilla ARGS="20 1"
make inject ARGS="20 1"
```

`LENGTH` must be smaller than the internal 1024-byte buffer. `OFFSET` is added
to each generated character.

## Running without the container

If you already have the tools installed locally, set these variables before
running `make`:

```bash
export GOBLINT_DIR=/path/to/goblint
export WITNESS_INJECT=/path/to/witness_inject
make
```

`GOBLINT_DIR` must contain `bin/goblint` and the Goblint example configuration
under `share/goblint/conf/examples/very-precise.json`.
